# Lab0 게임 모드: 월드·이동 프로토타입 명세

문서 상태: Draft v0.2
프로토타입 이름: Traversal Prototype
대상: Lab0의 기존 Viewer 기능을 유지하면서 추가하는 첫 번째 Game 모드

## 1. 목적

이 프로토타입은 퍼즐, 전투, 서사 없이 다음 질문만 검증한다.

> 고정 사선 시점의 룸 기반 3D 월드를 걷고 대시하며 한 바퀴 탐험하는 행위가 그 자체로 즐거운가?

검증 대상은 다음 네 가지다.

1. 걷기와 대시의 조작감이 즉각적이고 예측 가능한가?
2. 룸을 넘나들면서 하나의 연결된 장소를 탐험한다고 느끼는가?
3. 고정 사선 카메라에서 길, 장애물, 높낮이와 출구가 잘 읽히는가?
4. 되돌아왔을 때 플레이어가 월드의 구조와 랜드마크를 기억하는가?

## 2. 프로토타입의 약속

플레이어는 작은 숲과 유적을 통과해 가장 높은 전망대의 표식을 확인한 뒤, 아래쪽 길로 내려와 시작 지점으로 돌아온다.

- 예상 첫 플레이 시간: 3~5분
- 숙련 후 한 바퀴 시간: 60~90초
- 카메라: 회전하지 않는 직교 사선 카메라
- 이동: 화면 기준 8방향 걷기와 고정 거리 대시
- 월드: 수작업으로 만든 7개 룸과 하나의 복귀 루프
- 완료 조건: 전망대 표식에 접근한 뒤 시작 지점으로 복귀

## 4. 공간 모델

월드는 3D로 렌더하지만 게임 규칙은 2.5D로 제한한다.

- X축: 화면의 좌우와 일치
- Z축: 화면의 위아래와 대응
- Y축: 높이
- 월드 1단위는 약 1미터로 취급
- 플레이어는 XZ 평면에서 이동하며 현재 보행면이 Y 위치를 결정
- 자유 점프는 없으며 이동 가능한 경사와 단차만 자동으로 따라감
- 시각용 메시와 게임용 충돌 형상을 분리

룸은 동일한 크기의 타일이 아니라 다음 세 가지를 소유하는 공간 단위다.

- 하나 이상의 입구와 출구
- 카메라 이동 경계
- 룸 진입 및 복귀 위치

룸의 시각적 경계는 사각형 벽으로만 만들지 않는다. 숲길, 절벽, 좁은 유적 통로, 다리와 고도 변화로 다음 룸을 자연스럽게 가린다.

## 5. 월드 그래프

```text
       [R06 아래쪽 길]◀── 일방통행 하강 ──[R05 전망대 / 목표]─[R04 계곡 건널목]
              │                                                       │
       [R00 시작 숲]────────[R01 숲길]────────[R02 중앙 유적]────[R03 넓은 숲]
```

`R03 넓은 숲`은 선택적으로 방문하는 막다른 공간이다. 진행에 필요하지 않지만 중앙 유적에서 다른 방향으로 나갈 수 있다는 감각과 랜드마크 기억을 검증한다.

| ID | 이름 | 대략적인 크기 | 주요 검증 항목 |
| --- | --- | --- | --- |
| R00 | 시작 숲 | 16×10m | 작은 룸, 고정 카메라, 출발·복귀 인식 |
| R01 | 숲길 | 18×8m | 좁고 긴 룸, 카메라 추적, 전경 가림 |
| R02 | 중앙 유적 | 20×16m | 큰 룸, 카메라 경계, 여러 출구의 가독성 |
| R03 | 넓은 숲 | 18×14m | 선택형 막다른 길, 강한 랜드마크 |
| R04 | 계곡 건널목 | 18×10m | 고정 거리 대시와 짧은 틈 통과 |
| R05 | 전망대 | 14×10m | 고도, 목표 확인, 지나온 공간 조망 |
| R06 | 아래쪽 길 | 22×16m | 일방통행 하강, 긴 복귀 동선, 루프 완성 |

### 랜드마크 원칙

각 룸은 실루엣만으로 구분되는 랜드마크를 하나 가진다.

- R00: 큰 죽은 나무
- R01: 길 위로 기울어진 두 그루의 나무
- R02: 깨진 원형 석조 구조물
- R03: 밝은 풀과 거대한 나무 밑동
- R04: 좁은 계곡과 부서진 다리
- R05: 멀리서도 보이는 발광 표식
- R06: 길게 이어진 통나무와 낮은 안개

색만으로 룸을 구분하지 않는다. 색각과 스타일 프리셋이 달라져도 형태와 배치로 장소를 알아볼 수 있어야 한다.

## 6. 플레이어 이동

### 기본 파라미터

아래 값은 첫 구현값이며 플레이 테스트에서 조정할 수 있다.

| 항목 | 초기값 | 허용 튜닝 범위 |
| --- | ---: | ---: |
| 최대 이동 속도 | 3.6m/s | 3.0~4.4m/s |
| 가속도 | 28m/s² | 20~40m/s² |
| 감속도 | 36m/s² | 28~50m/s² |
| 충돌 반지름 | 0.32m | 0.28~0.38m |
| 시각적 캐릭터 높이 | 약 1.7m | 에셋에 맞춰 정규화 |
| 자동 단차 높이 | 0.25m | 0.15~0.35m |
| 최대 보행 경사 | 35도 | 30~40도 |
| 아날로그 입력 데드존 | 0.20 | 0.15~0.25 |

### 걷기 규칙

- 이동 입력은 화면 기준이다.
- 위 입력은 화면 위쪽으로, 오른쪽 입력은 화면 오른쪽으로 이동한다.
- 대각선 입력은 정규화하여 축 방향보다 빨라지지 않는다.
- 방향 전환은 즉시 반영한다.
- 가속과 감속은 짧게 적용하되 미끄러지는 느낌을 만들지 않는다.
- 캐릭터는 마지막 유효 이동 방향을 바라본다.
- 이동 속도가 작으면 Idle, 임계값 이상이면 Move 애니메이션을 재생한다.
- 애니메이션 속도는 실제 수평 속도에 비례하지만 충돌 위치에 영향을 주지 않는다.

### 대시 파라미터

| 항목 | 초기값 | 허용 튜닝 범위 |
| --- | ---: | ---: |
| 대시 시간 | 0.16초 | 0.12~0.20초 |
| 대시 속도 | 10m/s | 8~12m/s |
| 기본 이동 거리 | 1.6m | 1.3~2.0m |
| 대시 후 재사용 대기 | 0.24초 | 0.18~0.35초 |
| 입력 버퍼 | 0.10초 | 0.08~0.15초 |
| 대시 가능한 최대 틈 | 1.1m | 0.8~1.3m |

### 대시 규칙

- 이동 입력이 있으면 해당 방향으로 대시한다.
- 이동 입력이 없으면 마지막으로 바라본 방향으로 대시한다.
- 대시 중에는 방향을 바꿀 수 없다.
- 대시는 고정 시간 동안 진행되며 별도의 스태미나를 사용하지 않는다.
- 벽에 정면으로 닿으면 즉시 멈춘다.
- 벽에 비스듬히 닿으면 접선 방향으로 제한적으로 미끄러진다.
- 대시 중 짧은 비보행 영역을 건널 수 있다.
- 대시 종료 위치가 보행면이 아니면 대시 시작 위치로 복귀한다.
- 대시가 끝난 프레임부터 일반 이동 입력을 다시 반영한다.
- 대시 중에는 좀비의 돌진 피격 판정을 받지 않지만 적을 공격하거나 관통하지 않는다.

### 이동 상태

```text
GROUNDED
    ├── 이동 입력 → GROUNDED
    └── 대시 입력 → DASHING

DASHING
    ├── 시간 종료 → GROUNDED
    ├── 정면 충돌 → GROUNDED
    └── 유효하지 않은 착지 → 대시 시작 위치로 복귀 → GROUNDED

ROOM_TRANSITION
    └── 카메라·플레이어 전환 종료 → GROUNDED
```

## 7. 충돌과 보행면

- 플레이어의 수평 충돌은 발 위치를 중심으로 한 원형 충돌체를 사용한다.
- 캐릭터의 머리, 팔과 장식은 충돌 범위에 포함하지 않는다.
- 나무, 벽과 바위는 단순화된 원, 캡슐 또는 볼록 영역으로 충돌한다.
- 장식용 풀과 작은 나뭇가지는 충돌하지 않는다.
- 충돌 해결은 프레임 속도가 아니라 고정 시뮬레이션 tick에서 처리한다.
- 이동 속도가 높은 대시는 시작점과 끝점 사이를 연속 검사하여 얇은 벽을 통과하지 않는다.
- 플레이어가 유효한 보행면에 있을 때 마지막 안전 위치를 갱신한다.
- 절벽이나 월드 바깥으로 벗어나면 0.15초 동안 사라진 뒤 마지막 안전 위치로 복귀한다.
- 복귀에는 체력 손실이나 다른 페널티가 없다.

### 좀비 적

좀비는 전투 대상이 아니라 이동 선택을 압박하는 회피형 장애물이다. R02의
주 동선 밖에 한 마리, 선택형 R03 회피 아레나에 여섯 마리를 배치한다.
현재 비주얼은 `assets/godotman.glb`를 임시로 사용하며 `run`을 순찰·추격,
`attack`을 공격 예고·돌진, `idle`을 회복 상태에 매핑한다.

```text
SHAMBLING → CHASING → WINDUP → LUNGING → RECOVERING
     ▲          └── 감지 상실·기억 종료 ─────────────┘
```

- 평소에는 두 개의 수작업 순찰점 사이를 0.72m/s로 왕복한다.
- 7m 안의 넓은 전방 시야로 플레이어를 감지하며 장애물은 시야를 막는다.
- 10m 안에서 발생한 대시는 시야와 무관하게 듣는다.
- 감지 후 2.4초 동안 마지막으로 확인한 위치를 1.65m/s로 추격한다.
- 1.35m 안에서 공격 방향을 고정하고 0.46초 동안 바닥에 공격선을 예고한다.
- 돌진은 0.22초 동안 7m/s로 진행되며 종료 후 0.62초 동안 회복한다.
- 대시 중인 플레이어는 돌진에 맞지 않는다.
- 피격 시 체력을 차감하지 않고 플레이어와 현재 룸의 좀비를 입구 상태로
  되돌리며 누적 피격 횟수만 HUD에 남긴다.
- 모든 상태와 위치는 고정 60Hz 시뮬레이션에 포함되어 동일 입력 리플레이가
  동일한 결과를 만든다.

## 8. 카메라

### 투영과 방향

- 직교 투영
- 16:9 화면
- 카메라 yaw는 고정하며 월드 X축이 화면 가로와 일치
- 지면 기준 약 52도의 하향 시점에서 시작
- 플레이어가 카메라를 회전하거나 확대할 수 없음
- 초기 직교 세로 범위는 약 8m

카메라는 플레이어의 발이 아니라 몸 중앙보다 약간 낮은 지점을 추적한다. 높은 모델과 낮은 모델을 교체해도 화면 구도가 크게 달라지지 않도록 추적 높이는 월드 기준으로 유지한다.

### 룸 내 추적

- 작은 룸은 룸 중심에 카메라를 고정한다.
- 큰 룸과 긴 복도에서는 플레이어가 화면 데드존을 벗어날 때만 추적한다.
- 초기 데드존은 화면 너비의 14%, 높이의 10%다.
- 이동 방향 look-ahead는 최대 0.7m다.
- 카메라 목표는 약 0.12초의 부드러운 감쇠로 따라간다.
- 최종 카메라 위치는 룸별 카메라 경계를 벗어나지 않는다.
- 카메라의 렌더 위치는 안정된 월드 원점을 기준으로 저해상도 픽셀 격자에 스냅한다.
- 스냅 기준을 매 프레임 플레이어 위치로 바꾸지 않는다.

### 가림 처리

- 레벨 제작 단계에서 출구와 보행로를 가리는 큰 전경 오브젝트를 최소화한다.
- 카메라와 플레이어 사이를 가리는 것으로 표시된 메시만 일시적으로 숨긴다.
- 가림이 끝나면 즉시 다시 표시한다. 게임 셰이더에 객체별 알파가 추가되면 35% 페이드로 교체할 수 있다.
- 페이드 중에도 해당 오브젝트의 충돌은 유지한다.
- 플레이어의 실루엣은 모든 정상 보행 위치에서 읽을 수 있어야 한다.

카메라 흔들림과 연출용 확대는 프로토타입 범위에서 제외한다.

## 9. 룸 전환

- 각 연결부는 출구 영역, 대상 룸, 대상 입구와 진입 방향을 가진다.
- 플레이어 중심이 출구 임계선을 완전히 넘으면 전환을 시작한다.
- 전환 시간의 초기값은 0.30초다.
- 전환 중 입력을 잠시 비활성화한다.
- 플레이어를 대상 입구 안쪽 0.8m 지점까지 일정하게 이동시킨다.
- 카메라는 두 룸의 진입 구도를 smoothstep으로 보간한다.
- 화면 암전이나 로딩 표시는 사용하지 않는다.
- 완료 후 0.15초 동안 같은 연결부의 역방향 재진입을 막는다.
- 이전 룸은 최소한 전환이 끝날 때까지 렌더 상태를 유지한다.

룸 전환은 이동 흐름을 잠깐 정리하는 구두점이어야 하며 실패나 보상처럼 느껴지면 안 된다.

## 10. 일방통행 하강

R05 전망대에서 R06 아래쪽 길로 내려가는 연결은 프로토타입의 유일한 일방통행 이동이다.

- 지정된 가장자리에 접근하면 하강 가능 표시를 보여준다.
- 이동 방향을 가장자리 쪽으로 유지하면 자동으로 내려간다.
- 별도의 상호작용 버튼은 사용하지 않는다.
- 0.35초 동안 짧은 이동 연출을 수행한다.
- 착지 후 즉시 일반 이동이 가능하다.
- 반대 방향으로는 올라갈 수 없다.

자유로운 절벽 낙하나 임의 위치의 낙하는 지원하지 않는다.

## 11. 목표와 진행 상태

- R05의 발광 표식에 일정 거리 이내로 접근하면 `overlook_reached` 상태가 된다.
- 버튼 입력은 요구하지 않는다.
- 표식은 색, 밝기와 움직임으로 접근 전부터 알아볼 수 있어야 한다.
- 목표 도달 후 R06을 거쳐 R00으로 돌아오면 프로토타입 완료다.
- 완료 시 이동을 막지 않고 간단한 플레이 시간과 대시 횟수만 표시한다.
- 완료 상태에서도 계속 이동하거나 다시 시작할 수 있다.

진행 상태는 현재 룸, 마지막 안전 위치, 전망대 도달 여부, 시작 시간만 필요하다.

## 12. 입력

| 행동 | 키보드 | 게임패드 |
| --- | --- | --- |
| 이동 | WASD 또는 방향키 | 왼쪽 스틱 또는 D-pad |
| 대시 | Space | 아래쪽 face 버튼 |
| 현재 룸 시작점으로 복귀 | R | Back/View 버튼 |
| 개발 오버레이 | F3 | 없음 |
| 종료 | Cmd/Ctrl+Q | 없음 |

- 키보드와 게임패드가 동시에 입력되면 마지막으로 유효한 방향 입력을 사용한다.
- 텍스트 입력이나 Viewer UI가 열려 있지 않은 Game 모드에서만 이동 입력을 소비한다.
- 게임패드 진동은 프로토타입 범위에서 제외한다.

## 13. 시뮬레이션

- 이동과 충돌은 고정 60Hz tick으로 실행한다.
- 렌더 프레임 속도와 시뮬레이션 속도를 분리한다.
- 프레임에서 수집한 이동 방향과 대시 press를 다음 고정 tick에서 소비한다.
- 대시 press는 0.10초 동안 버퍼링한다.
- 한 렌더 프레임에 여러 tick이 실행돼도 대시 press를 중복 소비하지 않는다.
- 긴 프레임 이후 한 번에 처리하는 tick 수에는 상한을 둔다.

동일한 초기 위치와 입력 시퀀스는 동일한 tick의 위치와 룸 상태를 만들어야 한다.

## 14. 렌더링과 화면 구성

- 내부 게임 출력 해상도는 우선 256×144로 고정한다.
- 1280×720 창에서는 정확히 5배 nearest-neighbor 확대한다.
- 전체 게임 장면에 기존 셀 셰이딩, 다운샘플과 윤곽선을 적용한다.
- Viewer의 중앙 lens, magnifier, 모델 Inspector와 격자는 Game 모드에 표시하지 않는다.
- 개발 오버레이와 완료 텍스트는 다운샘플 이후 화면 해상도에 그린다.
- 배경색은 현재 Cel Style과 별도의 게임 월드 설정으로 유지한다.
- 플레이어의 화면상 높이는 256×144 기준 약 18~24픽셀을 목표로 한다.

첫 프로토타입은 기존 숲 관련 에셋을 사용하되, 충돌과 보행로가 읽히지 않으면 단색 디버그 메시를 우선한다. 장식 밀도보다 이동 가독성이 우선이다.

## 15. Viewer 및 기존 기능 보존

- `odin run .`은 기존 Viewer로 실행되어야 한다.
- Game 모드는 `odin run . -- --mode game`으로 진입한다.
- 기존 `--capture-*` 인자와 기본값의 의미를 변경하지 않는다.
- Viewer의 모델 선택, 애니메이션, 카메라, Lens, Cel Style, 단축키와 PNG 캡처 출력은 Game 모드 추가 전과 동일해야 한다.
- Game 모드에서 Inspector와 Viewer 단축키는 Game 입력으로 전달되지 않는다.
- 공통 렌더 파이프라인을 사용하더라도 Viewer composite의 픽셀 결과를 변경하지 않는다.

Game 모드의 숨은 창 검증을 위해 고정된 룸 시작 위치를 캡처할 수 있어야 한다. 구체적인 CLI 표면은 구현 단계에서 기존 캡처 옵션과 충돌하지 않도록 정하되, 최소한 R00, R02, R04의 정적 시작 장면을 재현 가능하게 캡처해야 한다.

## 16. 개발 오버레이

F3으로 다음 정보를 한 번에 토글한다.

- 현재 룸 ID와 룸 이름
- 플레이어 위치, 속도와 이동 상태
- 플레이어 충돌 원
- 마지막 안전 위치
- 보행 가능 영역과 비보행 영역
- 벽 충돌 형상
- 출구 영역과 진입 방향
- 카메라 목표, 데드존과 룸 카메라 경계
- 고정 tick 수와 렌더 FPS

개발 오버레이는 일반 Game composite 캡처에서는 기본적으로 꺼져 있어야 한다.

## 17. 완료 기준

### 기능

- Viewer를 변경 없이 실행할 수 있다.
- Game 모드에서 R00부터 R06까지 한 바퀴를 완주할 수 있다.
- 키보드와 게임패드로 동일한 이동과 대시가 가능하다.
- 모든 룸 입구를 양방향으로 오갈 수 있으며, R05→R06만 일방통행이다.
- 전망대 도달과 시작점 복귀가 정확히 한 번 완료로 판정된다.
- R 키로 현재 룸의 안전한 시작 위치로 복귀할 수 있다.

### 이동 품질

- 대각선 이동이 축 이동보다 빠르지 않다.
- 대시 거리는 프레임 속도에 따라 달라지지 않는다.
- 대시가 얇은 벽을 통과하지 않는다.
- 벽 모서리를 스칠 때 플레이어가 쉽게 끼이지 않는다.
- 유효하지 않은 틈에 떨어져 진행 불가능 상태가 되지 않는다.
- 룸 전환 직후 같은 출구로 즉시 되돌아가는 루프가 발생하지 않는다.

### 카메라와 가독성

- 모든 정상 보행 위치에서 플레이어의 발 위치를 판단할 수 있다.
- 큰 룸에서 카메라가 룸 바깥을 과도하게 노출하지 않는다.
- 카메라 이동 중 픽셀 격자가 불필요하게 흔들리지 않는다.
- 각 룸의 출구와 대표 랜드마크가 배경과 구분된다.
- 처음 플레이한 사용자가 완료 후 대략적인 월드 연결을 설명할 수 있다.

### 회귀와 검증

- `odin test .`가 통과한다.
- Game 모드 추가 전후의 대표 Viewer 캡처가 byte-identical하다.
- 새 바이너리로 Game 모드의 R00, R02, R04 숨은 창 캡처를 생성할 수 있다.
- Game 캡처의 PNG 크기, 포맷, 해상도와 비어 있지 않은 픽셀 출력을 확인한다.
- 같은 시작 상태의 Game 캡처를 두 번 실행하면 대응 출력이 byte-identical하다.

## 18. 구현 순서

1. 대표 Viewer 캡처와 해시를 기준선으로 저장한다.
2. `--mode game` 진입과 빈 Game 화면을 추가한다.
3. R00 회색 상자 공간에서 고정 tick 걷기와 충돌을 구현한다.
4. 대시, 연속 충돌 검사와 안전 위치 복귀를 구현한다.
5. 고정 사선 카메라, 데드존, 카메라 경계와 픽셀 스냅을 구현한다.
6. R00, R01, R02를 연결하고 룸 전환 감각을 조정한다.
7. 전체 7개 룸 그래프와 복귀 루프를 완성한다.
8. 기존 숲·캐릭터 에셋으로 공간을 드레싱한다.
9. 가림 처리, 애니메이션과 시각적 피드백을 추가한다.
10. 이동 수치와 룸 크기를 플레이 테스트로 조정한다.
11. Viewer 회귀 캡처와 Game 결정론적 캡처를 검증한다.

## 19. 프로토타입 종료 조건

다음 중 하나를 판단할 수 있을 때 프로토타입은 목적을 달성한다.

- 현재 이동과 월드 구조가 즐거우며, 그 위에 퍼즐을 설계할 가치가 있다.
- 이동은 좋지만 룸 전환 또는 카메라가 탐험 감각을 해치므로 해당 부분을 다시 설계해야 한다.
- 빈 월드 이동만으로는 충분한 재미가 없으며, 대시 또는 공간 구조에 새로운 핵심 이동 규칙이 필요하다.

이 판단 전에는 퍼즐 장치, 전투 시스템이나 장기 콘텐츠 제작을 시작하지 않는다.
